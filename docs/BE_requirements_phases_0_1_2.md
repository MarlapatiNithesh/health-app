## 1. Overview & Purpose of Each Phase

| Phase | Name | Goal | Duration |
|---|---|---|---|
| **0** | Project Foundation | Monorepo scaffold + PostgreSQL + API Gateway (auth, consent, audit, rate-limit) | 3–5 days |

## 6. Phase 0 — API Gateway Requirements

### 6.1 What to Build

The API Gateway is the **single entry point** for all client requests. It must:
1. Validate JWT tokens on every protected route
2. Check patient consent before any data-touching request
3. Write an audit log row for every request (pass or fail)
4. Enforce rate limiting
5. Reverse-proxy to downstream services

### 6.2 Middleware Execution Order

Every request must pass through this exact chain:

```
Request
  → Rate Limiter
  → Audit Logger (wraps response.end)
  → [Public routes: /auth, /health] → skip auth/consent
  → Auth Middleware (validate JWT)
  → Consent Middleware (check DB)
  → Reverse Proxy → patient-service OR document-service
```

### 6.3 Auth Middleware Spec

```typescript
// Input: Authorization: Bearer <jwt_token>
// On success: attaches req.user = { userId, email, iat, exp }
// On failure: 401 { error: "Missing or invalid Authorization header" }
//             401 { error: "Token expired or invalid" }
```

### 6.4 Consent Middleware Spec

```typescript
// Checks: Consent table where userId = req.user.userId
//         AND scope = 'data_access'
//         AND granted = true
//         AND revokedAt IS NULL
// On missing consent: 403 { error: "Patient consent not granted for data access" }
```

### 6.5 Auth Routes (`/auth`)

| Method | Path | Body | Response | Notes |
|---|---|---|---|---|
| POST | `/auth/register` | `{ email, password }` | `201 { userId, email }` | Hash password with bcryptjs (rounds: 12) |
| POST | `/auth/login` | `{ email, password }` | `200 { token, expiresIn }` | JWT signed with `JWT_SECRET` |
| POST | `/auth/consent` | `{ scope, granted }` | `200 { consentId }` | Requires auth. Upsert consent record |

### 6.6 Rate Limiting Rules

```
Window: 15 minutes (900,000 ms)
Max requests: 100 per IP per window
On exceeded: 429 { error: "Too many requests, please try again later" }
```

### 6.7 Phase 0 Acceptance Criteria

- [ ] `GET /health` → `200 { status: "ok", timestamp: "<ISO>" }`
- [ ] `POST /auth/register` creates User row and hashes password (no plaintext in DB)
- [ ] `POST /auth/login` returns signed JWT with correct `userId` in payload
- [ ] Unauthenticated request to `/patients/*` → `401`
- [ ] Valid JWT but no consent → `403`
- [ ] Every request (200, 401, 403, 404, 500) writes an `AuditLog` row
- [ ] 101st request in 15-minute window → `429`
- [ ] `prisma migrate dev` runs cleanly with zero errors
- [ ] `prisma studio` shows all tables with correct columns

## 7. Phase 1 — Patient 360 API Requirements

### 7.1 Service: `apps/patient-service` (port 3001)

The Patient Service owns all CRUD operations for the Patient 360. The API Gateway proxies `/patients/*` to this service.

### 7.2 Complete API Endpoint Catalogue

#### Patient Profile

| Method | Path | Body | Response | Notes |
|---|---|---|---|---|
| POST | `/patients/:userId/profile` | See schema below | `201 PatientProfile` | Creates profile linked to User |
| GET | `/patients/:patientId` | — | `200 Patient360` | Full profile + active conditions + active meds + allergies + last 20 labs |
| PUT | `/patients/:patientId/profile` | Partial profile fields | `200 PatientProfile` | Only demographics + preferences |

### 7.3 Provenance Rule — Non-Negotiable

> [!CAUTION]
> **Every clinical write (condition, allergy, medication, lab result) MUST create a Provenance record first and attach `provenanceId`.** Any code that writes to these tables without `provenanceId` is a bug. This will be checked in code review.

```typescript
// Enforce this pattern for ALL clinical writes:
async function withProvenance<T>(
  source: {
    sourceType: 'document' | 'manual_entry' | 'wearable' | 'lab_api' | 'user_input';
    sourceDate: Date;
    documentId?: string;
    pageNumber?: number;
    extractionModel?: string;
    modelVersion?: string;
    confidence?: number;
  },
  writer: (provenanceId: string) => Promise<T>
): Promise<T> {
  const provenance = await prisma.provenance.create({ data: source });
  return writer(provenance.sourceId);
}
```

### 7.4 Cross-User Isolation Rule

Every route handler that takes `:patientId` must verify the patient belongs to the authenticated user:

```typescript
// In every patient service route:
const patient = await prisma.patientProfile.findUnique({
  where: { patientId: req.params.patientId }
});
if (!patient) return res.status(404).json({ error: 'Not found' });
if (patient.userId !== req.user.userId) return res.status(403).json({ error: 'Forbidden' });
```

### 7.5 Soft-Delete Rule

Conditions, allergies, medications, and lab results must **never** be hard-deleted. Set `deletedAt = new Date()`. All GET queries must filter `where: { deletedAt: null }`.

### 8.4 Background Job Architecture

**Concurrency:** 2 workers  
**Retry:** 3 attempts with exponential backoff

### 8.5 Extraction Pipeline — Step by Step

The `runExtractionPipeline(documentId, filePath)` function must execute these steps in order:

```
Step 1: Update HealthDocument.extractionStatus = 'processing'
Step 2: OCR → raw text string
Step 3: NER → array of medical entities from Python service
Step 4: Normalize entities → map to RxNorm/LOINC codes where possible
Step 5: Score confidence per field
Step 6: Create ONE Provenance record for this extraction run
Step 7: Write ExtractedField rows (one per entity)
         - confidence >= 0.85 → status = 'confirmed'
         - 0.60-0.84 → status = 'pending'
         - < 0.60 → status = 'review_needed'
Step 8: Auto-commit HIGH confidence (>= 0.85) fields to Patient 360
Step 9: Update HealthDocument.extractionStatus = 'done'
```

### 8.8 Normalization Requirements

|---|---|---|

### 8.9 Confidence Gating — The Three Tiers

| Score Range | Tier | `status` value | Action |
|---|---|---|---|
| `>= 0.85` | HIGH | `confirmed` | Auto-write to Patient 360 immediately |
| `0.60 – 0.84` | MEDIUM | `pending` | Hold in `ExtractedField`, surface to user for confirmation |
| `< 0.60` | LOW | `review_needed` | Do not write to Patient 360, do not surface to user |

**Confidence score formula:**
```typescript
function computeScore(entity: NEREntity, rxNormCode?: string): number {
  let score = 0.70;                        // base NER score
  if (rxNormCode) score += 0.15;           // RxNorm match = high confidence
  if (entity.text.length > 3) score += 0.05;
  // Add more heuristics as NER improves
  return Math.min(score, 1.0);
}
```

| `fieldName` | Write to | Also write HealthEvent |
|---|---|---|

| `diagnosis` | `MedicalCondition` table | `eventType: 'diagnosis'` |
| `lab_value` (with `lab_test` context) | `LabResult` table | `eventType: 'lab_result'` |
| `allergy` | `Allergy` table | `eventType: 'allergy'` |

**All writes must use `provenanceId` from the extraction run's Provenance record.**
